# Fix plan for the 2026-09-26 adversarial review

Tracks how every finding of [`2026-09-26-adversarial-review.md`](2026-09-26-adversarial-review.md) (PR #13) is being
addressed. Work is cut into **packages** with disjoint file ownership so they can run in parallel; each package lives on
its own branch, is fixed and then independently verified by a second agent, lands as its own draft PR, and is squash-merged
to `main` as soon as it passes. This file is the ledger: update it whenever a package changes state.

Orchestration: one central session plans, launches and merges; the fixing and verifying agents run on Opus with a shared
workflow script (`fixpkg.js`: fix → verify → re-fix up to twice). Branch prefix: `claude/clever-hypatia-ma6t1l-`.
Tracking PR: the `claude/clever-hypatia-ma6t1l` branch (this file and the review document).

## Resuming after an interruption (usage cap, session loss)

1. `git fetch origin && git branch -r | grep clever-hypatia` — every package branch that exists was pushed by its fixer.
2. Open PRs: `gh pr list` (or the GitHub UI) filtered on the branch prefix; a package with an open PR is fixed or under
   verification; a merged PR means done — mark it below.
3. For a package without a PR: its fixer did not finish. Re-launch it with the package spec below (scope + findings +
   verify) on the existing branch if one exists (keep its commits), otherwise from `origin/main`.
4. Waves are ordered by dependency (below). Never start wave 2 (notebook edits) before `w1-build` has merged: it
   regenerates every percent-source notebook once (stable cell ids), and notebook edits before that would conflict.
5. After each wave: regenerate the Colab index (`python3 tools/gen_colab_index.py`) and the site nav
   (`python3 tools/site/build_site_content.py`), `mkdocs build --strict`, `python3 tools/orchestration/mdlinks.py` on the
   changed `.md` files, and refresh this ledger, `STATUS.md` and the `CLAUDE.md` decisions log.

## File ownership rules (wave 1)

Owned by nobody in wave 1 (so no package edits them): `CLAUDE.md`, `tools/orchestration/STATUS.md`, the eight layer
`README.md` files, every `.ipynb`, every notebook source (`notebooks_src/*.py`), `tools/gen_colab_index.py` runs.
`mkdocs.yml` is only ever regenerated by `tools/site/build_site_content.py`, never hand-edited.
