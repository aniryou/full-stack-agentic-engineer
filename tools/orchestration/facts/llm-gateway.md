## 1. OpenAI chat-completions contract (`openai-openapi/openapi.json`, `components.schemas`)
Request `CreateChatCompletionRequest` (required: `model`, `messages`):
- `stream` (bool, default false); `stream_options` → `ChatCompletionStreamOptions` = object `{include_usage: bool, include_obfuscation: bool}` or null. Siblings of `include_usage`: only `include_obfuscation` (adds an `obfuscation` string to chunks; on by default). No `continuous_usage_stats` in OpenAI's spec (that is vLLM's).
- `include_usage` description, verbatim core: "an additional chunk will be streamed before the `data: [DONE]` message. The `usage` field on this chunk shows the token usage statistics for the entire request, and the `choices` field will always be an empty array. All other chunks will also include a `usage` field, but with a null value. **NOTE:** If the stream is interrupted, you may not receive the final usage chunk".
- `max_completion_tokens` (int): "An upper bound … including visible output tokens and reasoning tokens". `max_tokens`: `deprecated: true`, "deprecated in favor of `max_completion_tokens`, and is not compatible with o-series models".
- `user`: `deprecated: true` — "being replaced by `safety_identifier` and `prompt_cache_key`". **Both exist**: `safety_identifier` (string, maxLength 64), `prompt_cache_key` (string). Also `prompt_cache_options` {`ttl` (only `30m`), `mode` `implicit`|`explicit`} and a deprecated `prompt_cache_retention` (`in_memory`|`24h`). (Spec note: prompt_cache_options is "Supported for `gpt-5.6` and later models".)
- `service_tier` → `ServiceTier` enum `auto`, `default`, `flex`, `scale`, `priority`, `fast` (default `auto`; response echoes the tier actually used, `fast` is reported as `priority`).
- `reasoning_effort` → enum `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` (default `medium`).
- `tools`; `tool_choice` = `none` | `auto` | `required` | named tool object; `parallel_tool_calls` (bool, default true); `response_format`; `seed` (**`deprecated: true`**, "Beta … best effort"); `n` (default 1); `store` (default false); `metadata`; `moderation`.
- The example model id in `ModelIdsShared` is `gpt-6-astra` (so "gpt-6-*" ids are real as of this spec).

Response / stream:
- `CreateChatCompletionResponse.object` = `"chat.completion"`; stream chunk `CreateChatCompletionStreamResponse.object` = `"chat.completion.chunk"`; chunk required: `choices`, `created`, `id`, `model`, `object`; optional `usage` (nullable), `service_tier`, `obfuscation`, `system_fingerprint` (deprecated).
- Stream choice required `delta`, `finish_reason` (nullable), `index`. `finish_reason` enum: `stop`, `length`, `tool_calls`, `content_filter`, `function_call` (deprecated).
- `ChatCompletionStreamResponseDelta`: `content`, `refusal`, `role`, `tool_calls[]`, deprecated `function_call`. **No `reasoning_content`/`reasoning`** field in OpenAI's schema (reasoning is a vLLM/DeepSeek extension; see §2).
- `ChatCompletionMessageToolCallChunk`: required **`index`** only; `id`, `type` (`function`), `function.{name, arguments}` all optional — the first delta for a call carries `id`+`name`, later deltas carry `arguments` fragments keyed by `index`; an accumulator must concatenate by index.
- `CompletionUsage` (required `prompt_tokens`, `completion_tokens`, `total_tokens`): `prompt_tokens_details.{cached_tokens, audio_tokens, text_tokens, image_tokens, cache_write_tokens}`; `completion_tokens_details.{reasoning_tokens, audio_tokens, text_tokens, accepted_prediction_tokens, rejected_prediction_tokens}`. `reasoning_tokens` are part of `completion_tokens` ("still counted in the total completion tokens for purposes of billing").
- Errors: `ErrorResponse = {error: Error}`, `Error` required `type`, `message`, `param` (nullable), `code` (**string** or null).
- POST `/chat/completions` responses (openapi.yaml ~l.2413): 200 (`application/json` or `text/event-stream`), 400, 401, 403, 404, 429 (`#/components/responses/InferenceRateLimited`), 500, 503 (`InferenceServiceUnavailable`). 429 example: `type: rate_limit_error`, `code: slow_down`; 503 example: `type: service_unavailable_error`, `code: server_is_overloaded`.
- **`Retry-After` is in the spec** for 429 and 503: integer ≥ 1, "minimum number of seconds to wait … may be omitted".
- **`data: [DONE]`** for chat completions appears in the spec only inside the `include_usage` description (and in the Assistants run stream); the chat `stream` description points at prose docs. Keep the terminator `(verify)` in prose, but it is safe to emit.
- **`x-ratelimit-{limit,remaining,reset}-{requests,tokens}` are NOT in the spec** (only `X-RateLimit-*-Images` on an images endpoint). Prose-docs only → primer keeps them `(verify)`.

## 4. MCP authorization, client side (`modelcontextprotocol/docs/specification/2026-07-28/basic/authorization/`)
Four pages: `index.mdx`, `authorization-server-discovery.mdx`, `client-registration.mdx`, `security-considerations.mdx`. **"DPoP" appears in none** (grep of 2026-07-28, draft and `docs/extensions/auth/`).
- PRM discovery (discovery l.39–49): servers implement `WWW-Authenticate` `resource_metadata` on 401 **or** a well-known URI — path form `https://example.com/.well-known/oauth-protected-resource/public/mcp`, then root `…/.well-known/oauth-protected-resource`. Clients **MUST** support both, use the header URL when present, else try the well-known URIs in that order. PRM **MUST** include `authorization_servers` (≥ 1); separate registration state per AS (l.30–33).
- AS metadata (l.64–94). Issuer with a path (`https://auth.example.com/tenant1`), in order: (1) `/.well-known/oauth-authorization-server/tenant1`, (2) `/.well-known/openid-configuration/tenant1`, (3) `/tenant1/.well-known/openid-configuration`. Issuer without path: (1) `/.well-known/oauth-authorization-server`, (2) `/.well-known/openid-configuration`. The document's `issuer` **MUST** equal the issuer used to build the URL, else reject.
- Scope (index l.97–135): use `scope` from the 401 `WWW-Authenticate` if given, else all of PRM `scopes_supported` (omit `scope` if undefined). Runtime insufficient scope → **403** + `WWW-Authenticate: Bearer error="insufficient_scope", scope="…", resource_metadata="…"` (l.332–345). Step-up (l.379–405): new scope set = **union** of previously requested scopes and the challenge's; retry "no more than a few times"; `client_credentials` clients MAY step up or abort.
- Registration priority (client-registration l.13–18): (1) pre-registered, (2) CIMD if AS metadata has `client_id_metadata_document_supported: true`, (3) DCR if `registration_endpoint`, (4) prompt the user. CIMD is **SHOULD**; DCR is **MAY** and **"deprecated"** (Warning block l.140). CIMD client rules (l.38–42): HTTPS URL **with a path**, document includes at least `client_id`, `client_name`, `redirect_uris`; `client_id` equals the document URL exactly; MAY use `private_key_jwt`. AS rules (l.46–51): validate `client_id` match, cache per HTTP headers, validate redirect URIs, valid JSON with required fields.
- PKCE (security-considerations l.50–61): MUST implement PKCE, **MUST use `S256`**, and **MUST refuse** when `code_challenge_methods_supported` is absent (for both RFC 8414 and OIDC metadata; OIDC ASes MUST publish it).
- `resource` (index l.215–252): RFC 8707 `resource` **MUST be in both authorization and token requests**, the canonical MCP server URI, sent even if the AS ignores it; prefer no trailing slash.
- `iss` (index l.190–213, SEP-2468 **Final**): record the issuer with the PKCE verifier; table: supported=true & iss absent → reject; iss present → simple string compare (no case folding or normalisation); both absent → proceed. On mismatch do not act on `error*` fields either.
- Tokens: `Authorization` header on **every** HTTP request; never in the query; clients MUST NOT send tokens not issued by the MCP server's AS; servers MUST NOT accept or transit other tokens (index l.258–297).
- Refresh (index l.299–313; cites OAuth 2.1 **draft-14** §4.3): keep refresh tokens confidential, SHOULD list `refresh_token` in `grant_types`, MAY add `offline_access` if in AS `scopes_supported`, MUST NOT assume one is issued. security-considerations l.34: "For public clients, authorization servers **MUST rotate refresh tokens**" (OAuth 2.1 draft-13 §4.3.1). Elsewhere the spec cites draft-13.
- SEP statuses (`seps/`): SEP-991 (CIMD) **Final**; **SEP-1046 (client credentials) Final** — delivered as the extension `io.modelcontextprotocol/oauth-client-credentials` (`docs/extensions/auth/oauth-client-credentials.mdx`: JWT Bearer assertions, RFC 7523, recommended; `client_id`+`client_secret` also supported); enterprise-managed authorization is the extension `io.modelcontextprotocol/enterprise-managed-authorization` (IdP issues an **ID-JAG** the client exchanges at the MCP AS). Both live in `modelcontextprotocol/ext-auth`, negotiated under `io.modelcontextprotocol/clientCapabilities`. SEP-414 **Final**: trace context in `params._meta` as `traceparent`, `tracestate`, `baggage`.
- Reference client (`python-sdk/src/mcp/client/auth/oauth2.py`): `TokenStorage` protocol = `get_tokens`, `set_tokens`, `get_client_info`, `set_client_info` — **one store per server**, not per principal; `OAuthClientProvider(…, client_metadata_url=…)`; `should_use_client_metadata_url()` = AS advertises `client_id_metadata_document_supported` **and** a valid URL, else DCR (`utils.py` l.372); `is_valid_client_metadata_url`: https and path not `""`/`"/"`; `_refresh_token()` sends `grant_type=refresh_token`, `refresh_token`, `client_id` and `resource` (when PRM known or protocol ≥ 2025-06-18); `_handle_refresh_response` keeps the old refresh token if the AS omits one (no rotation) and clears tokens on non-200.

## 5. OAuth 2.1 and CIMD drafts
- `oauth-v2-1/draft-ietf-oauth-v2-1.md` (`docname: draft-ietf-oauth-v2-1-latest`; Document History tops at **-16**: removes PKCE `plain`, makes the AS send `iss`). Whether -16 is published: (verify). Section numbers computed from headings: §4.1.1 Authorization Request, §4.3 Refresh Token Grant, **§4.3.1 Token Endpoint Extension** (refresh), §7.5.1 Authorization Code Injection, §7.5.2 PKCE "plain" Code Challenge Method.
- Reuse detection, verbatim (l.2094–2112): ASes "MUST utilize one of these methods to detect refresh token replay … for public clients": sender-constrained refresh tokens (DPoP RFC 9449 or mTLS RFC 8705) **or** rotation — "issues a new refresh token with every access token refresh response. The previous refresh token is invalidated but information about the relationship is retained … one of them will present an invalidated refresh token … it will revoke the active refresh token as well as the access authorization grant associated with it."
- CIMD (`draft-ietf-oauth-client-id-metadata-document.md`, history tops at **-02**; MCP links -00): client_id URL MUST be `https`, have a path, no userinfo, no dot segments, no fragment, SHOULD NOT have a query; simple string comparison; document served with 200, `client_id` equals the fetched URL; no shared-secret auth methods (`client_secret_post`, `client_secret_basic`, `client_secret_jwt`), no `client_secret`, public keys only (`jwks`/`jwks_uri`). AS: SHOULD fetch, MAY cache honouring RFC 9111 with its own bounds, **MUST NOT cache errors or invalid documents**, advertise `client_id_metadata_document_supported`; SSRF: **MUST NOT fetch URLs resolving to RFC 6890 special-use addresses** (loopback allowed only for a loopback AS in dev); **recommended maximum read 5 kilobytes**; ASes that also mint ids SHOULD NOT mint ones starting `https://`.

## 6. DPoP nonces (`draft-dpop/main.md` = draft-ietf-oauth-dpop-16 → RFC 9449)
Section numbers (computed from headings, matching RFC 9449): §4 DPoP Proof JWTs (§4.2 syntax, §4.3 checking), §5 access token request (§5.1 AS metadata), §6 public key confirmation (`cnf.jkt`), §7 protected resource access (§7.1 `DPoP` auth scheme), **§8 Authorization Server-Provided Nonce** (§8.1 syntax, §8.2 providing a new nonce), **§9 Resource Server-Provided Nonce**, §11.1 proof replay.
- Header: `typ: dpop+jwt`, `alg` asymmetric (**MUST NOT be `none` or a MAC**), `jwk` public only. Claims: `jti` (≥ 96 bits random or UUIDv4), `htm`, `htu` (no query/fragment), `iat`; `ath` = base64url(SHA-256(access token)) when presenting a token; `nonce` when a server supplied one.
- AS metadata `dpop_signing_alg_values_supported` (JSON array of JWS algs).
- AS nonce: **400** `{"error":"use_dpop_nonce"}` + `DPoP-Nonce` header; same code on nonce mismatch; at most one `DPoP-Nonce` header; nonce opaque, unpredictable, syntax `1*NQCHAR`. RS nonce: **401** + `WWW-Authenticate: DPoP error="use_dpop_nonce"` + `DPoP-Nonce`.
- Lifetime/caching: a server MAY send a fresh nonce on any response, including a **200** ("more efficient"); the client uses the latest nonce for all subsequent requests **to that server** until replaced; "clients need to keep only one nonce value and servers keep a window of recent nonces"; nonce-bearing responses should be `Cache-Control: no-store`; browsers need `Access-Control-Expose-Headers: DPoP-Nonce`. No numeric lifetime is set.
- Repo gap confirmed: `agentsec.identity.tokens.DPoP.proof(key, *, method, url, access_token=None, nonce=None)` (RS256, `typ` `dpop+jwt`, `jwk`, `jti` uuid4 hex, `htu` stripped of query/fragment, optional `ath`, `nonce`) and `DPoP.verify(proof, *, method, url, access_token=None, expected_jkt=None, seen_jti=None, max_age=300)` — **verify never issues or checks a nonce** (`06-gateway/identity-security/agentic-identity-gcp-lab/src/agentsec/identity/tokens.py` l.414–480).

## 7. SPIFFE Workload API and SVID rotation
- `spiffe/standards/SPIFFE_Workload_Endpoint.md`: gRPC over UDS preferred; TCP only if the server can "strongly authenticate the workload based on source IP" (l.39); every request MUST carry gRPC metadata **`workload.spiffe.io: true`** (SSRF hardening, l.41); TLS MUST NOT be required; `SPIFFE_ENDPOINT_SOCKET` = `unix:///abs/path` (no authority) or `tcp://IP:port` (l.49–55).
- `SPIFFE_Workload_API.md`: `FetchX509SVID` and `FetchX509Bundles` return **server streams**; `FetchJWTSVID` unary, `FetchJWTBundles` stream, `ValidateJWTSVID` unary (l.121–249); every stream message carries **the full state**, absence = redaction (l.79–91); clients keep the stream open and reconnect immediately (l.73).
- SPIRE defaults (`spire/doc/spire_server.md` l.71–72; `pkg/server/credtemplate/builder.go` l.34–38): `default_x509_svid_ttl` **1h**, `default_jwt_svid_ttl` **5m**.
- Rotation (`spire/pkg/common/rotationutil/rotationutil.go`): `shouldRotateByHalf` rotates when `ttl <= calculateJitteredHalfLife(lifetime)`, jitter = **± 10 % of the half-life** (`halfLife/10`). For a 1 h SVID: rotate when 27–33 min remain (half-life 30 min ± 3 min). JWT-SVIDs always use the half-life rule.
- Availability target (`spire/doc/spire_agent.md` l.82, l.271–275): agent setting **`availability_target`**, no default (unset); "if set, must be at least 24h"; rotate an X.509 SVID when remaining lifetime reaches it (jittered 0 to +10 min, `calculateJitteredAvailabilityTarget`); needs a grace period (`lifetime − availability_target`) ≥ **12h** (`gracePeriodThreshold`) else falls back to half-life; does not affect JWT-SVIDs.
- Long-lived upstream connections: **(unverified — not in the standards)**: an established TLS session keeps the certificate from its handshake; a rotated SVID is used only on new handshakes, so a gateway that pools long-lived connections should rebuild its TLS config from the stream (go-spiffe style `GetCertificate`) and cycle connections before the old SVID expires.

Pass `now` from the caller or use `redis.call('TIME')` (allowed in scripts from Redis 5 with effects replication; default in 7). In Redis Cluster all keys of one script must share a hash slot (`{tenant}` hash tags). LiteLLM's working example is §8.
- For reserve → reconcile: the script debits the reservation; a second script (or `INCRBY` with a negative delta) refunds `reserved − actual` at stream end; cut streams reconcile with the estimate.

## Pitfalls
1. `stream_options` on a non-streamed request is a **400 in vLLM**; inject `include_usage` only when `stream: true`, and strip the usage chunk (the `choices: []` chunk) when the client did not ask (LiteLLM's `_litellm_strip_stream_usage` does exactly this).
2. The final usage chunk is lost on disconnect/cancel (OpenAI spec note) — meter cut streams from counted deltas (labelled estimate) and never bill 0.
3. vLLM reports a **mid-stream error as a `data:` JSON chunk with HTTP 200**, then `[DONE]`; a relay that only checks the status meters it as success.
4. vLLM `ErrorInfo.code` is an **int** (HTTP status); OpenAI's `Error.code` is a **string** (`slow_down`, `server_is_overloaded`) — normalise.
5. Fall back only before the first byte: once a chunk is relayed, surface the error (a `data: {"error":…}` chunk), do not splice another model's output.
6. Tool-call deltas key on **`index`**; only the first carries `id` and `function.name`; `arguments` arrive as string fragments and may be invalid JSON.
7. Reasoning text is **`reasoning`** in vLLM 0.30.0 (it renames `reasoning_content` on input); OpenAI has neither; Anthropic uses `thinking_delta`; Gemini reports `thoughtsTokenCount` **outside** `candidatesTokenCount` — add it to output for billing; Anthropic `input_tokens` **excludes** cache reads/writes — add them for `prompt_tokens` and for OTel `gen_ai.usage.input_tokens`.
8. `scalelab.capacity.cost_per_call` takes `input_tokens` **including** cached ones; feeding Anthropic's `input_tokens` directly double-discounts.
9. `prompt_tokens_details` is `None` from vLLM unless `--enable-prompt-tokens-details`; `reasoning_tokens` only with `--reasoning-parser`.
10. `--enable-force-include-usage` also turns on **continuous** usage in every chunk — do not sum per-chunk usage; take the last.
11. `cache_salt`: ≤ **128** chars, no `@ / \ NUL`, non-empty; it salts the first block only; derive it from the verified tenant, never a header, and keep it secret (HMAC of tenant id with a gateway key, 43-char base64url for 256 bits).
12. Priority directions differ: vLLM `priority` **lower = earlier** (needs `--scheduling-policy priority`, else non-zero errors); llm-d `InferenceObjective.priority` **higher = served first**; Envoy `backendRefs.priority` 0 = primary. Map tiers explicitly.
13. vLLM `--api-key` guards only `/v1`, `/v2`, `/inference`; never expose the engine port — the gateway holds the provider key.
14. `service_tier`: OpenAI accepts `fast` (echoed as `priority`); vLLM's Literal rejects `fast`.
15. `x-ratelimit-*-requests/-tokens` headers are not in the OpenAPI spec; `Retry-After` is (integer seconds ≥ 1). Anthropic SDK also reads `retry-after-ms` and `x-should-retry`.
16. OTel names are moving: `cache_creation` (v1.41.0) vs `cache_write` (main); `gen_ai.client.token.usage` (v1.41.0, Envoy AI GW) vs `gen_ai.client.inference.*` (main). Pin one set and say which; `gen_ai.provider.name` is **required** and has no self-hosted value.
17. OTLP/JSON: hex trace/span ids, integer `kind`, int64 and nanosecond timestamps as **strings** — a naive `json.dumps` of ints fails round-trip tests against the spec example.
18. MCP: DPoP is **not** in MCP 2026-07-28 — `DPoP-Nonce` handling is RFC 9449 §8/§9, labelled as such. The HMAC signer stand-in violates RFC 9449 §4.2 (asymmetric `alg` only): label it and never call it DPoP-conformant. DPoP-bound tokens use `Authorization: DPoP <token>` + a `DPoP` proof header, not `Bearer`.
19. MCP: refuse when `code_challenge_methods_supported` is absent; send `resource` in **both** requests; union scopes on step-up; validate `iss` per the table; the metadata `issuer` must equal the URL's issuer; tokens per (principal, resource, scopes) — the Python SDK stores one per server.
20. Refresh rotation: a reused (already-rotated) refresh token must revoke the **whole grant**, active token included (OAuth 2.1 §4.3.1 text quoted in §5).
21. CIMD fetch at the fake AS: 5 KB read cap, no special-use IPs (loopback only for a loopback AS in tests), never cache errors.
22. SPIRE jitter is ± 10 % **of the half-life** (27–33 min for a 1 h SVID), not ± 10 % of the lifetime; `availability_target` ≥ 24h and needs ≥ 12h grace.
23. Workload API calls must send `workload.spiffe.io: true` metadata; messages carry full state (absence = revoke).
24. Envoy AI Gateway and a naive per-request bucket both debit tokens **after** the response — concurrent long streams over-admit a provider TPM; LiteLLM v3 reserves an estimate (default 4,096 output tokens when `max_tokens` is absent).
25. Portkey OSS's exact cache key has no tenant; LiteLLM's semantic cache defaults to `semantic_cache_scope="key"`. The gwcore cache must namespace by tenant (and by user for personal classes) before lookup.
26. NeMo output rails default `stream_first: True` — tokens reach the user before the rail sees them; a held-back window needs `stream_first: False` (adds ≈ chunk_size tokens × ITL to TTFT). Prompt Guard 2 has a 512-token window.
27. Embeddings primer §15's semantic-caching text is the sub-section "Embeddings elsewhere in agent systems" (l.372), not a §15 of that name.
28. The self-hosted L4 row is $0.660 from `tokens_per_s` 294.39 (roofline model), not from the rounded 294 ($0.661).
29. Kong OSS has no semantic cache or token rate limiting (Enterprise `ai-semantic-cache`, `ai-rate-limiting-advanced`); don't credit them to OSS.
30. The spec's `07.2` breaker (consecutive failures) and `scalelab`'s breaker (failure ratio in a window) differ — say which `gwcore.routing` follows.
