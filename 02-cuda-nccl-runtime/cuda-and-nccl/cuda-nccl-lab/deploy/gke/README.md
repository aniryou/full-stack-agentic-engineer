# deploy/gke — GPU workloads on GKE (T3)

**What it does:** runs the lab's GPU checks on the cluster from `../gcp/terraform` (or any GKE
cluster with L4 nodes): a smoke test that captures how a pod sees its GPU, a CUDA sample, nccl-tests
across two L4s, GPU time-sharing, a MIG slice, and DCGM alert rules for Google Managed Prometheus.

**Cost:** each Job brings up a Spot GPU node from zero and releases it when the pod finishes (the
cluster autoscaler removes an unneeded node after about ten minutes — verify for your version).
An L4 Spot node for 15 minutes is cents; the 2 x L4 node for nccl-tests about twice that (verify
current Spot prices). Nothing here runs indefinitely except `04-time-sharing.yaml` — delete it.

**Cleanup:** `./run.sh clean` (deletes the `gpu-lab` namespace), then `terraform destroy` in
`../gcp/terraform`.

| Manifest | Pool it lands on | What to look at |
|---|---|---|
| `00-namespace.yaml` | — | everything lives in `gpu-lab` |
| `01-gpu-smoke.yaml` | `l4` (g2-standard-4) | `probe.sh` output: `/dev/nvidia*`, the `/usr/local/nvidia` driver mount, versions → `python -m gpurt.container --log out/gpu-smoke.log` |
| `02-cuda-vectoradd.yaml` | `l4` | "Test PASSED": image CUDA runtime + node driver agree |
| `03-nccl-tests-2gpu.yaml` | `l4x2` (g2-standard-24) | `nvidia-smi topo -m`, NCCL's transport (`NCCL_DEBUG=INFO`), busbw → `python -m gpurt.nccltests out/nccl-tests-2gpu.log` |
| `04-time-sharing.yaml` | `l4-shared` | two pods, one GPU UUID; scale to 3 and the third stays Pending |
| `05-mig.yaml` | `a100-mig` | `nvidia-smi -L` lists a `MIG 1g.5gb Device` |
| `06-dcgm-alert-rules.yaml` | — | GMP `Rules` generated by `gpurt.dcgm.rules_manifest()`; do not edit by hand |

```bash
$(terraform -chdir=../gcp/terraform output -raw get_credentials)
./run.sh status        # nodes, accelerator/sharing labels, allocatable nvidia.com/gpu
./run.sh smoke         # -> out/gpu-smoke.log
./run.sh vectoradd
./run.sh nccl          # -> out/nccl-tests-2gpu.log (first run: node scale-up + image pull, 10+ minutes)
./run.sh timeshare     # needs enable_time_sharing_pool = true
./run.sh mig           # needs enable_mig_pool = true and A100 quota
./run.sh rules         # DCGM alert rules; then Cloud Monitoring -> Alerting
DRY_RUN=1 ./run.sh nccl   # print the kubectl commands only
```

Every GPU pod requests `nvidia.com/gpu` in `limits` (extended resources cannot be overcommitted,
so requests equal limits), selects an accelerator with `cloud.google.com/gke-accelerator`, and
tolerates the `nvidia.com/gpu` taint. How the device plugin turns that request into device nodes
and a driver mount is primer §6; how the scheduler places it is layer 03
(`03-kubernetes-gpu/gpu-scheduling`).

DCGM metrics: with `enable_dcgm = true` GKE scrapes the exporter for you; in *Metrics explorer*
switch to PromQL and try `DCGM_FI_PROF_SM_ACTIVE`, `DCGM_FI_DEV_GPU_UTIL`,
`DCGM_FI_PROF_DRAM_ACTIVE` while `./run.sh nccl` runs (metric availability per GKE version: verify).
Notebook 06 explains what each field means and why `GPU_UTIL` alone misleads.

Items marked `VERIFY:` in the manifests (image tags, GKE node-label values, MIG profiles) are product
details to re-check against current documentation before relying on them.
