# agentic-scaling-lab — size, protect and price an agent service, on a hosted API or your own GPUs

After this lab you can take "100,000 conversations a day" to tokens per minute, turns in flight, a capacity request
and dollars in two minutes; show the overload feedback loop and the mechanisms that break it (smoothing, jittered
retries, breakers, degrade levels, shedding); and say at what GPU price a self-hosted vLLM fleet beats the API.

## Start here

1. Read [`docs/01-scaling-primer.md`](docs/01-scaling-primer.md) Parts 1–3 (about 45 min): why agents scale
   differently, and the arithmetic.
2. `python -m pip install -e ".[dev]" && python -m scalelab.capacity` — the capacity plan in a second; then
   `python -m pytest -q` (37 tests, ~3 s).
3. Open [`notebooks/01_scaling_math.ipynb`](notebooks/01_scaling_math.ipynb) and work through 01–04; then
   `05_hosted_or_own_gpus` for the fleet.

## Run it

```bash
python -m venv .venv && source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m scalelab.capacity                 # the Gemini capacity plan
python -m scalelab.mistral                  # Mistral's API or a fleet: the plan, the fleet, the break-even
```

## The code (`scalelab/`, about 1,800 lines with docstrings)

| Module | The idea |
|---|---|
| `capacity.py` | conversations → turns → calls → tokens/min; Little's law; Provisioned Throughput units and break-even; cost per conversation; what breaks first (Gemini) |
| `mistral.py` | the same on Mistral's API — the rate-limit request, cost per conversation — plus the fleet sized for peak, the break-even GPU price and the two-replica floor |
| `serving.py` | one vLLM replica: KV bytes per token (GQA vs MLA) → resident sequences; HBM bandwidth → time per token; batch ↔ throughput; TTFT from prefill FLOPs (first-principles estimates) |
| `model.py` | a fake model on three backends — a hosted API (a shared pool that answers 429), a fleet (that queues and slows down), the hybrid — with prefix caching; `fake_model(provider)`; the real Gemini and vLLM calls |
| `resilience.py` | token bucket, backoff with full jitter, circuit breaker, `call_with_retries` bounded by a deadline |
| `admission.py` | degrade levels 0–3 from in-flight turns, pushback ratio, queue age and (on the Mistral scenario) backend saturation; an in-flight cap; shedding with `Retry-After`; hysteresis |
| `loop.py` | the turn: budgets on four dimensions, a checkpoint per step, idempotent writes, resume after a crash |
| `tools.py` | simulated CRM / billing systems with QPS ceilings and structured errors |
| `sim.py` | a load generator: many users against any backend; latency, shedding, spill-over share and cost per regime; the backend switch |
| `clock.py` | the virtual clock, and a virtual-time event loop for deterministic tests |

The notebooks use their own check helper (`nbutil.py`, beside `scalelab/`): an exercise is a `todo()` placeholder rather than
`# YOUR CODE HERE`, and a check prints `PASS`, `FAIL` or `---- not attempted yet` rather than a ✅. Practice notebooks
(`notebooks/`) run end to end untouched; their solutions (`solutions/`, the same file names) run with every check passing.

## The anchor numbers (verify before quoting — prices, limits and GPU rates move)

**Gemini, 5 September 2026.** 100 k conversations/day → 15 model calls/s average, 46 at peak, 153 in an incident →
4.6 / 13.75 / 45.8 M input tokens per minute against a 10 M TPM Flash tier baseline → 42 / 125 / 417 turns in flight →
$0.068 per conversation with routing and caching ($0.14 without) → 69 GSUs of Provisioned Throughput for the base
load, break-even at 75 % utilisation on a 1-year term. What breaks first is the token budget, then the billing
mainframe; Cloud Run is about 0.1 % of the bill.

**Mistral and a fleet, 19 September 2026.** The same demand is 4.8 / 14.3 / 47.7 M total tokens per minute → a
rate-limit request of 60 RPS and 19 M TPM → $0.0131 per conversation on the planning mix (90 % Small 4 + 10 % Medium
3.5, cached; $39.7 k/month) → or Ministral 3 14B on H100s: batch 24 at 20 ms per token (estimate), 4 / 11 / 34
replicas, $55 k/month on on-demand GPUs → the fleet beats the API whenever an H100-hour costs less than about $4.95,
so residency decides the path and the arithmetic prices the decision.

## Caveats

- Every latency and throughput number is simulated (the load tests) or estimated from first principles (a replica);
  replace them with a load test against staging and `vllm bench serve` on the target GPUs before anyone buys GPUs.
- Prices, limits and model ids are dated (5 and 19 September 2026) and marked `(verify)` in the docs.
